# Score Watcher 機能概要

Score Watcher は、競技クイズのスコア管理と表示に特化した Web アプリケーションです。Google アカウントでログインして利用し、プレイヤー・問題・ゲームのデータはすべてサーバー（Turso）に保存されます。現場での迅速なスコアリングから、大規模なイベントでの公開・観戦まで幅広い用途をサポートします。

## アカウントとデータ

利用には Google アカウントによるサインインが必要です。サインインすると、プレイヤー・問題・ゲームのデータがサーバーに保存され、どの端末からでも同じデータを扱えます。ユーザー設定ページからは表示設定（テーマ、ヘッダーの表示有無、問題番号の表示、勝ち抜けポップアップ、スコアの表記など）を変更でき、これらの設定は得点表示画面にも反映されます。同じページからアカウントの削除も行えます。アカウントを削除すると、保存されているデータもすべて削除されます。

## プレイヤー・問題の管理

プレイヤー管理では、個別追加、タブ区切りやカンマ区切りテキストの貼り付け、CSV インポートに対応し、一覧では検索と一括削除が行えます。問題管理も同様に読み込み・インポートの導線を持ち、セット名や問題番号を含む基本項目を扱えます。いずれの操作も API Routes 経由で実行され、結果は即座に画面へ反映されます。

## ゲームの作成と設定

形式一覧ページから形式を選択してゲームを作成します。作成後は設定ページで、形式ごとのオプション（勝ち抜けポイント、失格誤答数など）、限定問題数と勝ち抜け人数、プレイヤーの並び順や初期スコア、問題セットの紐づけ、Discord Webhook、公開設定を調整できます。設定ページからはゲームのコピー・エクスポート・リセット・削除も行えます。エクスポートした JSON はゲーム一覧の「ゲームをインポート」から復元できます。

## 得点表示

得点表示画面は、ゲームごとのスコア計算ロジックに基づいてリアルタイムに表示を更新します。数秒間隔でログを取得し直すため、複数の端末で同じボードを開いていても操作が反映されます。ヘッダーにはゲーム名と形式の要約、問題番号を表示でき、問題セットが紐づく場合は進行に合わせて問題文・解答を表示します。画面下部のゲームログには解答者の一覧が並び、問題セットが紐づいている場合は問題文と答えも合わせて確認できます。

誤操作に備えて操作ログを保持しており、「一つ戻す」で直前の操作を取り消せます。想定外の進行や限定問題数での判定に使える「スコアの手動更新」モードも用意しており、スコアの表示値や背景色を直接調整できるほか、問題番号を手動で前後させることもできます（手動更新モードでの変更はログには記録されません）。プレイヤーの勝ち抜けは画面中央に大きく表示され、スマートフォン等の外部画面でも視認性を保った表示が可能です。

## 観戦モード

公開設定にしたゲームは、認証不要の観戦モード（`/viewer/[game_id]`）を通じて共有できます。観戦用 URL はゲーム設定の「公開設定」欄からコピーでき、ゲーム一覧からも開けます。観戦ページは数秒ごとに最新の状況を取得し、プレイヤー名・所属・得点と直近のゲームログを表示します。表示内容は Cloudflare Workers KV にキャッシュされており、得点操作のたびに更新されます。

Discord Webhook を設定したゲームでは、勝ち抜けやリセットのイベント時に自動で通知が送られます。これにより、会場外の視聴者や運営メンバーへの即時共有が可能になります。

## 対応ゲーム形式とスコア計算

スコア計算は形式ごとに独立したロジックで実装され、共通インターフェースで統一的に扱われます。対応している形式は次のとおりです：normal、nomx、nomx-ad、ny、nomr、nbyn、nupdown、divide、swedish10、backstream、attacksurvival、squarex、z、freezex、endless-chance、variables、aql。各形式の仕様は `docs/rules/` 以下にまとめられており、勝ち抜け・敗退条件やポイント遷移、特殊ルールなどの挙動を確認できます。限定問題数と勝ち抜け人数を設定した場合は、規定の問題数に到達した時点で順位に応じた勝ち抜け・敗退の判定が全形式に共通で適用されます。

## 画面構成の概要

トップページではアプリの概要と主要機能の紹介、注意事項の案内を提供します（認証不要）。認証が必要なページはプレイヤー管理・問題管理・ゲーム一覧・ユーザー設定で、`src/app/(default)/(authed)/` 配下にまとまっています。形式一覧は認証なしでも閲覧でき、ゲームの作成時にログインが必要になります。得点表示画面と観戦ページは全画面レイアウトの `(board)` グループに属します。ドキュメントエリアにはアプリ情報、推奨環境、利用規約、プライバシーポリシー、商用利用に関する記載がまとまっています。

## 技術的な補足

アプリは Next.js App Router と TypeScript で実装され、UI には Mantine、スタイルは CSS Modules を採用しています。フロントエンドからのデータ取得は API Routes のみを使用し、Hono クライアントを介して行われます。サーバー側では Zod による厳密なスキーマバリデーションを行い、各機能のモデル定義は `src/models/` に集約されています。データベースは Turso（libSQL）を Drizzle ORM で操作し、サインインには Better Auth（Google OAuth）を使用します。これらの構成により、安定した表示と厳密なデータ整合性を両立しつつ、競技現場で必要な即応性を確保しています。
